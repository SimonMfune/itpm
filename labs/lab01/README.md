# Lab 1: Navigating the modern IT tool stack; Scrum and Kanban boards

**Chapters:** Chapters 1 and 2 of *Information Technology Project Management: Traditional Foundations, Agile Delivery and AI-Enhanced Practice*  

## Purpose
Set up the tools you will use all semester, and see how a Scrum board and a Kanban board control work differently.

## You will produce

1. A Jira space or Azure DevOps project for your capstone team, with ten starter work items.
2. A Scrum board with a two-week sprint, a Sprint Goal and a Definition of Done.
3. A Kanban board with a WIP limit on every in-progress column.
4. A half-page recommendation, using the suitability filter in Chapter 2, on which board your capstone team should use, and when each board suits a project.

## Steps

**Part 1 (Chapter 1).**

1. Create a free Jira Cloud site, or an Azure DevOps organisation, using your institution's email if your tutor asks you to.
2. Create a space (Jira) or project (Azure DevOps) for your capstone team and invite your team-mates.
3. Add ten starter work items for your capstone. Write each as an outcome ("Patient can book a video appointment"), not a vague task ("Do the booking"). Give each a type, a rough size and an owner.

**Part 2 (Chapter 2).**

4. Create a Scrum board. Start a two-week sprint with a Sprint Goal that states an outcome, not a list of items.
5. Write a Definition of Done that a tester could check. Include testing and review, not only "code complete".
6. Create a Kanban board for the same work. Make the columns match how your team really works, and set a WIP limit on every in-progress column. Note the reason for each limit.
7. Work through the suitability filter in Chapter 2 for your capstone, and write your recommendation.

## Tips

- A WIP limit that never stops anyone starting work is not a limit. Start low and raise it if the board shows a reason.
- Free plans and their limits change. Check the current terms before you start.
