# Lab 12: Agile retrospectives and project offboarding

**Chapters:** Chapter 12 of *Information Technology Project Management: Traditional Foundations, Agile Delivery and AI-Enhanced Practice*  
**Files:** `data/healthsync_retrospectives.csv`, `data/healthsync_incidents.csv`

## Purpose
Close a project and capture its lessons.

## You will produce

1. A start, stop, continue retrospective based on the HealthSync sprint records.
2. A lessons register with five lessons written as changes to practice.
3. An AI-assisted synthesis of the records, with your critique.
4. A closure checklist, including archiving a project repository in GitHub and a records retention note.

## The data

- `data/healthsync_retrospectives.csv`: notes from the retrospectives of Sprints 1 to 12, with the team, the type of note and the votes it received. Names are replaced with roles.
- `data/healthsync_incidents.csv`: the hypercare incident log.

## Steps

1. Read the records and run a start, stop, continue retrospective for the whole project. Keep it blameless.
2. Write five lessons as changes to practice, each with an owner and the place it will be built in (a template, checklist, standard or contract). Table 12.6 shows the form.
3. Use the synthesis prompt in Appendix A (A.4.12) on the records. Check every theme against its sources and write a critique: what the model got right, what it missed and what it should not have said.
4. Complete a closure checklist (Appendix C, Section C.11). Archive a practice repository in GitHub (Settings, Danger zone, Archive this repository) and write a short note on how long project records should be kept and why.

## Tips

- A lesson written as an observation ("communication was poor") changes nothing. Write what will be done differently, and by whom.
- Team records do not show everything. Ask what the governance records would add.

## Optional AI extension (Appendix A, Table A.5)

Synthesise themes from the sprint records, then rerun with the governance records. Patterns: A.4.12. Submit: Both outputs; your critique; final lessons register.

The lab deliverable must stand on its own, and your critique of the AI output is the part that is assessed. See `appendixA/`.
